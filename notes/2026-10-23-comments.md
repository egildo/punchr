# Finder comments, measured (2026-10-23)

Measured on scratch folders under the session's temporary folder, macOS 26.6.2, Finder never
restarted. The route had been tried by eye the day before, in the tabularium session: a comment
set through Finder's scripting showed AHEAD in the Comments column at once; one written only to
the attribute showed nothing until Finder rewrote `.DS_Store`.

- **Through Finder.** `tell application "Finder" to set comment of (POSIX file "<path>" as
  alias) to "<text>"` takes about 0.2 s from `osascript`, less from `NSAppleScript` in
  punchr's own process. It writes the folder's `com.apple.metadata:kMDItemFinderComment` (a
  binary property list holding one string) and a `cmmt` record for the folder in the parent's
  `.DS_Store`, creating the `.DS_Store` if there was none. No other attribute of the folder
  changes.
- **Clearing leaves a trace.** Setting the comment to empty leaves the attribute behind, holding
  an empty string, and an empty `cmmt` record in `.DS_Store`. punchr removes the attribute
  after Finder is done, so a struck and cleared folder is byte for byte what it was; the empty
  record in `.DS_Store` stays, as Finder's own.
- **Accents decomposed.** Finder stores `é` as `e` plus a combining accent. Swift compares
  strings by canonical equivalence, so a look's comment still matches what Finder stored.
  Quotes, backslashes and line breaks are kept as given.
- **What Finder shows.** `get comment` through Finder reads the `.DS_Store` copy. After punchr
  struck three scratch folders, Finder answered `AHEAD, BEHIND, AHEAD`, as struck; one check
  asks Finder the same way after the comment it writes.
- **The Comments column, by eye: not done this round.** A scratch window opened by script
  ignored the request to show the Comments column (Finder reports the column visible and draws
  none), and the View Options panel was out of reach without taking over the screen. The
  by-eye proof is still the tabularium session's, of the same Apple event.
- **Permission.** This Mac had already allowed the app the session runs in to control Finder,
  so no prompt appeared. Who macOS names in the prompt the first time (the terminal app punchr
  runs in, or punchr itself) was not seen. A refusal is error -1743; punchr turns it into a
  message pointing at System Settings → Privacy & Security → Automation.
