# Files wearing tags and comments (2026-10-23)

Scratch files under the session's temporary folder, macOS 26.6.2, Finder never restarted.

- **The grey dot, by eye.** A text file struck with the tag `untracked` (grey) showed a grey dot
  beside its date in an open Finder list view, without a restart; an untagged file beside it
  showed none, and a folder struck with the same look showed the dot and its grey tint. The tag
  attribute is the same on a file as on a folder: a binary property list of `"name\nN"`
  strings.
- **The comment on a file.** Finder's `set comment of (POSIX file … as alias)` works on a file
  as on a folder, with the same `cmmt` record in the parent's `.DS_Store`. A file struck with a
  tag and a comment and then cleared has every attribute byte for byte as before (a check).
- **Nothing else on a file.** punchr reads only a file's tags and comment. A file's own Finder
  information and resource fork, which can hold a custom icon, are never read or written; a
  look with a stamp or an icon is refused on a file before anything is written.
- **Aliases.** A Finder alias is a regular file, so it now wears tags itself; its original is
  not touched. Symbolic links are still refused.
