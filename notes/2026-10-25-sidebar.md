# The Finder sidebar: what can be changed (2026-10-25)

A research run (read-only, sources tagged) and one scratch test, macOS 26.6.2. Question: is there
a minimal sidebar feature punchr could offer?

## The scratch test

Two 20 MB APFS disk images were made in the session's scratchpad and mounted, then ejected and
deleted after Egildo looked.

- `punchr-icon`: the stand-in logo as `.VolumeIcon.icns` (a plain `icns`, 20,347 bytes, the same
  two PNGs punchr puts in a folder icon) at the volume's root, and the custom-icon bit set in the
  root's Finder information.
- `punchr-stamp`: the branch stamp, struck on the volume's root with `punchr strike`, exactly as on
  a folder.

Seen, without remounting:

| Where | `punchr-icon` | `punchr-stamp` |
|---|---|---|
| Sidebar, Locations | plain drive outline | plain drive outline |
| Desktop | the logo | the standard disk-image icon, no stamp |
| Finder window (list of `/Volumes`) | the logo | the standard disk-image icon, no stamp |

So a volume icon works everywhere except the sidebar, which always draws its single-colour
outline; a stamp does nothing on a volume's root.

## What the research found

- **The list of sidebar items** has no supported way to be edited. Apple deprecated the old
  interface (LSSharedFileList) without a replacement; the lists now live in `.sfl4` files under
  `~/Library/Application Support/com.apple.sharedfilelist/`, protected from a plain shell, in an
  undocumented format. `sfltool` lists them but cannot add or remove items. `mysides` and
  FinderSidebarEditor wrap the deprecated interface; no report shows them working on recent
  macOS.
- **Icons in the sidebar** are single-colour template images. A folder's custom icon or stamp is
  not shown there (secondary source; not tested here). One project reports that on macOS 26 a
  folder with its own icon can lose its sidebar outline altogether (unconfirmed).
- **A Finder Sync extension** can add a toolbar button, badges, and a contextual menu on sidebar
  items, and can give a monitored root folder that the user dragged into the sidebar its own
  template icon; that route is reported broken or flaky since macOS 11.
- **The Tags section** lists names from Finder's preferences (`FavoriteTagNames`: "In Corso",
  Giallo, Verde, Blu and an empty name here). Where their colours are kept was not found on this
  machine.

## How OneDrive gets its row (read from its bundle here)

OneDrive ships two extensions:

- `FinderSync.appex` (`com.apple.FinderSync`): badges and menus on files, the same kind as
  punchr's.
- `OneDrive File Provider.appex` (`com.apple.fileprovider-nonui`): this one makes the sidebar row.
  It registers a File Provider domain, which the system keeps at
  `~/Library/CloudStorage/OneDrive-simaggioli.it` and lists under Locations. The row's icon is
  declared in the extension's `Info.plist` as `CFBundleSymbolName = "odsymbol"`, a custom symbol
  in its `Assets.car`; Apple documents this as setting the Finder sidebar icon.

A File Provider extension is a sync engine: the system asks it for every item, its contents and
each change. It also needs an app group, which is believed to need a provisioning profile from
a paid developer account; ad-hoc signing is unconfirmed. A custom symbol needs an asset catalog
compiled by Xcode's `actool`, though a system SF Symbol name may do without one.

## For punchr

- **Volumes wear an icon**: works, shown on the desktop and in windows, not in the sidebar. A
  small feature if wanted; it writes a hidden `.VolumeIcon.icns` at the volume's root, which a
  record of that volume (tabularium's, for `/Volumes/Projects`) would see.
- **The sidebar itself**: out of reach without becoming a File Provider, which is a different
  product.
